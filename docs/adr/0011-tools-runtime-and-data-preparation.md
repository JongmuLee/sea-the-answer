# 0011. 해사 데이터 실행 Tool과 준비 작업을 나누고 기존 앱 선박에 명시적으로 연결한다

- 날짜: 2026-10-13
- 제안자: 손태호 (역할4)
- 관련: [ADR 0009](0009-split-packages-and-compose.md)(오프라인 `scripts/` 예외), [ADR 0010](0010-dbmate-migrations.md)(해사 스키마 범위 확장), [통합 계획](../plans/2026-10-13-tools-and-data-preparation-integration.md)

## 배경

팀 피드백은 실행 중 호출되는 Python Tool을 `backend/tools`로, 초기 자료 준비·적재를 최상위 `scripts`로 분리하고 해사 DDL도 기존 dbmate 흐름으로 통합하자는 것이다. 기존 앱의 `ships`와 `operations`는 선박과 일별 운항을 관리한다. 실제 MRV는 보고기간 단위이며 합성 Noon·원본 출처·품질 판정도 보존해야 하므로 기존 일별 JSON 기록에 전부 넣으면 의미와 추적성이 손실된다.

## 제안 결정

- 런타임은 `backend/tools/`, 다운로드 자료의 정규화·전처리·필드 사전 생성·CSV 적재·이전 환경 보조 작업은 `scripts/`에 둔다. `scripts/`는 오프라인 자료 준비용 최상위 소스 폴더의 예외다. 독립 패키지 매니저는 추가하지 않고 backend uv 환경과 선택 `data` 의존성 그룹을 사용한다.
- 기존 init 파일은 수정하지 않는다. 새 `migrations/20261013010000_maritime_data.sql`이 6개 해사 테이블과 2개 승인 View를 만든다. loader는 DDL을 실행하지 않고 이미 마이그레이션이 끝난 빈 테이블에만 한 트랜잭션으로 적재한다.
- 기본은 앱과 같은 `DATABASE_URL`이다. 별도 `MARITIME_DATA_DATABASE_URL`을 사용할 때도 해당 DB에 기본 앱 init과 해사 마이그레이션을 모두 적용한다. DB를 넘는 외래키는 지원하지 않는다.
- `maritime_data.vessels.ship_id`를 nullable 외래키로 두어 기존 `public.ships.id`를 재사용한다(`ON DELETE SET NULL`). 원본 `vessel_id`와 REAL/SYN 구분은 바꾸지 않는다. 검토한 명시적 매핑만 연결하고, 이름으로 자동 결합하거나 MRV 선박 전체를 앱 `ships`에 자동 생성하지 않는다. 연간 MRV를 일별 `operations`로 분해하지 않는다.
- 단일 이전 `role4` 또는 `maritime_data` 스키마는 새 마이그레이션에서 기대 구조를 검증한 뒤 채택한다. 양쪽이 함께 있거나 구조가 맞지 않으면 중단한다. 데이터가 있는 해사 스키마의 down은 삭제를 거절한다.
- 앱 JSON 백업은 기존 앱 테이블만 담는다. 앱 복구 전의 해사 선박 연결은 복구 후에도 동일한 선박 정체성이 확인되는 경우만 다시 연결한다. 누락·불일치는 미연결로 두고 건수를 기록한다. 전체 해사 데이터·원본·CSV는 PostgreSQL 백업과 별도 파일 백업으로 보관한다.
- 조회·계산 API의 Bearer 인증, 읽기 전용 트랜잭션, Decimal 정밀도, 출처·품질·단위, 공식 CII 미산출 계약은 유지한다. 같은 FastAPI에 마운트되어도 앱 사용자의 세션·CSRF를 적용한 화면 어댑터가 구현된 것은 아니다.

## 검토한 대안

| 대안 | 선택하지 않은 이유 |
|---|---|
| 모든 MRV·Noon을 `operations.body`로 변환 | 연간·일별 의미, 원본 행·품질·Partial 구분이 사라지고 현재 일별 유일키와 충돌 |
| 모든 외부 선박을 `ships`에 자동 등록 | 앱이 실제 관리하는 선박과 공개 자료의 대량 선박을 혼합하고 이름·IMO 확인을 생략 |
| 해사 DB를 항상 별도 DB로 유지 | 같은 DB 선박 외래키를 사용할 수 없고 설치·변경 이력이 이중화됨 |
| 적재 스크립트가 DDL도 실행 | dbmate 이력과 실제 구조가 어긋나며 데이터 적재가 스키마 변경 권한까지 요구 |

## 결과와 남은 범위

배포 시 스키마 변경 경로는 하나가 되고 런타임 이미지에는 준비 스크립트·무거운 전처리 의존성을 넣지 않는다. 기존 앱 선박을 재사용하면서 MRV·합성·출처·품질 모델을 보존한다. 마이그레이션은 CSV나 공개 자료를 다운로드하지 않는다. 사용자별 화면 연결, 영구 감사 통합, 항구 매핑, 검증된 공식 CII 입력 확보는 후속 범위다.
