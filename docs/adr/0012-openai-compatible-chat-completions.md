# 0012. 모델 공급자를 OpenAI 호환 Chat Completions로 연결

- 상태: 대체됨(0013)
- 날짜: 2026-10-13
- 결정자: 팀장 지시, 정호영 구현, 사용자 구현·PR 작성 승인
- 관련: [공급자 계약](../specs/llm-provider.md), [전환 계획](../plans/2026-10-13-openai-compatible-chat.md), [PR #8](https://github.com/dudco/sea-the-answer/pull/8)

## 배경

기존 호출은 OpenAI `/v1/responses`와 키·모델 설정에 고정되어 있어 동국 AI Chat이나 키 없는 로컬 Ollama로 주소를 바꿀 수 없었다. #8 이후 Python API 구조를 유지하면서 모델 호출 경계를 변경해야 한다.

## 결정

- 서버의 기존 `httpx`로 `<OPENAI_BASE_URL>/chat/completions`를 비스트리밍 호출한다. 기본 주소는 OpenAI이며 기존 `OPENAI_API_KEY`·`OPENAI_MODEL` 설정 이름을 유지한다.
- `api/config.py`가 설정을 해석하고 health·답변이 같은 판정을 사용한다. 사용자 지정 호환 서버는 키 생략을 허용하며 키가 있을 때만 Bearer 헤더를 보낸다.
- `api/llm.py`가 통신·JSON·인용 검증을 담당한다. `api/store/answers.py`는 권한 적용된 검색 근거 전달, 발췌 대체, 운항 분석·이력 저장을 유지한다.
- 기본 요청은 `model`, `messages`, `stream=false`만 사용한다. JSON object/schema 출력 강제는 공급자가 지원할 때 선택한다. 어떤 모드에서도 앱 내부 JSON·인용 검증을 생략하지 않는다.
- 오류나 잘린 응답·위조 인용은 모델 결과 전체를 폐기하고 기존 발췌 경고로 전환한다. 다른 공급자로 자동 재시도하지 않는다. 키·모델 서버 원본 오류를 공개 응답에 넣지 않는다.

## 검토한 대안

| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| Responses 전용 유지 | 기존 구현 유지 | 팀의 동국·Ollama 호환 요구를 충족하지 못함 |
| 공급자별 별도 SDK·분기 | 개별 특화 기능 활용 | 현재 요구는 공통 텍스트 답변이며 의존성과 분기가 불필요하게 늘어남 |
| 모든 공급자에 엄격한 JSON schema 강제 | 서버 출력 형식 보장 | 호환 서버·모델별 지원 차이; 기본은 공통 요청과 로컬 검증 사용 |

## 결과

- 주소·모델·키 설정으로 공급자를 전환할 수 있고, 모델 실패 시 기존 공개 API 계약을 유지한다.
- 기본 요청의 호환성을 위해 기존 `max_output_tokens=2200`은 전송하지 않는다. 답변은 여전히 최대 5개 문장으로 검증하지만 생성 토큰 한도는 서버·모델 설정에 의존한다. 모델 응답이 느리면 25초 타임아웃으로 발췌 전환될 수 있다.
- 실제 동국의 주소·모델·인증과 실제 Ollama 연결 성공은 별도 검증 대상이다. 모의 HTTP 테스트나 기본 e2e 통과가 이를 대신하지 않는다.
