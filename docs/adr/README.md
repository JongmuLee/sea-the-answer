# adr — 설계 결정 기록 (Architecture Decision Records)

나중에 바꾸기 어려운 선택을 **왜** 그렇게 했는지 남깁니다. 새로 합류한 사람이나 에이전트가 "이건 왜 이렇게 되어 있지?"라는 질문에 답을 찾는 곳이고, 같은 논의를 반복하지 않게 해 줍니다.

## 언제 쓰나

- 기술 스택, 저장소, 실행 구조, 인증·권한 방식, 모듈 경계, 외부 서비스 선택
- 대안이 여럿이었고 팀이 하나를 골랐을 때
- 기존 ADR의 결정을 뒤집을 때 (새 ADR로)

단순한 구현 세부, 일정, 작업 기록은 ADR이 아닙니다(→ `plans/`).

## 규칙

- 파일: `NNNN-주제.md` (4자리 번호, 마지막 번호 + 1, 영문 kebab-case). [`_template.md`](_template.md)를 복사합니다.
- 상태: `제안 → 채택 → 대체됨(NNNN) / 폐기`.
- **채택된 ADR의 본문은 고치지 않습니다.** 결정을 바꾸려면 새 ADR을 쓰고, 이전 ADR에는 상태 줄만 `대체됨(NNNN)`으로 바꿉니다. (오타 수정은 예외)
- 짧게 씁니다. 한 ADR에 결정 하나.
