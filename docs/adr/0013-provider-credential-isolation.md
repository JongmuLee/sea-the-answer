# 0013. 공통 LLM 설정과 공급자별 인증키를 URL 호스트로 격리

- 상태: 채택
- 날짜: 2026-10-14
- 결정자: 팀장 검토 의견, 정호영 수정·PR 작성 지시
- 관련: [이전 ADR 0012](0012-openai-compatible-chat-completions.md), [공급자 계약](../specs/llm-provider.md), [전환 계획](../plans/2026-10-13-openai-compatible-chat.md)

## 배경

PR #11은 모든 호환 서버에 하나의 `OPENAI_API_KEY`를 사용했다. OpenAI와 동국 AI Chat의 인증키는 발급처·권한·수명이 다르므로 URL만 바꿀 때 다른 서비스로 키가 전송될 수 있다. 공통 설정 이름도 특정 공급자에 묶여 있었다. ADR 0012의 통신·인용 검증 결정은 유지하며 설정·키 선택 정책을 대체한다.

## 결정

- 서버의 기존 `httpx`로 `<LLM_API_BASE_URL>/chat/completions`를 비스트리밍 호출한다. 기본 주소는 `https://api.openai.com/v1`이다. 공통 출력 옵션은 `LLM_RESPONSE_FORMAT`, 모델 이름은 기존 호환성을 위해 `OPENAI_MODEL`을 유지한다.
- `api/config.py:llm_settings()`가 URL을 파싱하고 health·답변이 같은 판정을 사용한다. 호스트가 정확히 `api.openai.com`이면 `OPENAI_API_KEY`, `dongguk.edu` 또는 `.dongguk.edu` 경계의 하위 도메인이면 `DONGUK_AI_CHAT_API_KEY`를 선택한다. 알려진 공급자 키가 비어 있으면 모델 비활성으로 판정한다.
- URL 경로·단순 부분 문자열로 공급자를 고르지 않는다. `OAOpenAI` 경로는 공급자 식별·공식 API 주소의 근거가 아니다. 다른 호환 서버와 로컬 Ollama는 두 키가 모두 설정되어도 빈 키를 사용하며 Authorization 헤더를 생략한다. 다른 공급자 키로 대체하지 않는다.
- `api/llm.py`가 통신·JSON·원문 인용 검증을 담당하고 `api/store/answers.py`는 권한 적용된 근거 전달·발췌 대체·운항 분석·이력 저장을 유지한다. 기본 요청은 `model`, `messages`, `stream=false`이며 JSON 형식 강제는 선택 사항이다. 실패·잘림·위조 인용은 전체 모델 결과를 폐기하고 기존 발췌 경고로 전환한다.
- 기존 `OPENAI_BASE_URL`·`OPENAI_RESPONSE_FORMAT`은 각각 `LLM_API_BASE_URL`·`LLM_RESPONSE_FORMAT`으로 이동하며 이전 이름의 별칭은 두지 않는다. 인증키·모델 서버 원본 오류를 공개 응답·로그에 노출하지 않는다.

## 검토한 대안

| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| 모든 서버에 하나의 키 사용 | 설정 수가 적음 | 공급자 전환 시 서로 다른 서비스로 키 전송 가능 |
| URL 경로·부분 문자열로 키 선택 | 공급자별 경로에 쉽게 대응 | 임의 호스트의 같은 경로와 유사 도메인으로 키가 전송될 수 있음 |
| 공급자별 SDK·별도 호출부 | 개별 기능 확장에 유리 | 현재 공통 텍스트 답변 요구에는 불필요한 의존성·분기 증가 |

## 결과

- 두 키를 함께 보관해도 대상 호스트에 맞는 키 하나만 선택하며 로컬 모델에는 외부 서비스 키를 전송하지 않는다.
- 다른 인증형 호환 서버·동국의 별도 외부 도메인은 자동으로 인증하지 않는다. 필요하면 공식 접속 정보를 확인하고 별도 키·호스트 계약을 추가한다. 동국의 공식 API 주소·경로는 아직 미확정이다.
- 배포 전 `.env`의 이전 URL·형식 키를 이름 변경하고 동국 인증키를 새 변수로 옮겨야 한다. 개인 `.env`·DB를 자동으로 수정하지 않는다.
- 기존 25초 타임아웃·최대 5문장 검증·기본 토큰 한도 미전송을 유지한다. 실제 동국·Ollama 접속은 모의 HTTP 검증과 별도로 확인한다.
