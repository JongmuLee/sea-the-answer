# 표·차트 응답과 입력량·시간 관측 계약

- 상태: 확정 (2026-11-03)
- 관련: [통합 답변](integrated-answer.md), [LLM 공급자](llm-provider.md), [작업 계획](../plans/2026-11-03-answer-presentation-and-load-validation.md)

## 1. 목적과 범위

10월 29일 교수 피드백에 따라 사용자가 요청한 표·차트의 질문 → API → 화면 표시를 연결하고, 입력량 증가에 따른 모델 시간·출력 오류를 재현한다. 기존 문장·인용·권한 계약은 유지한다. 새 이미지 생성·PDF 그림 자동 추출·검색 알고리즘 교체는 별도 범위다.

## 2. 요청과 표현

- `POST /api/ask` 요청 `outputFormat`: `auto`(기본), `text`, `table`, `chart`.
- 자동 모드는 질문의 명시적인 표·차트/그래프 요청을 해석한다. 일반 질문은 문장 응답이다. 새로운 그림/도식 생성 등 미지원 요청은 안내하며 임의의 이미지 URL·HTML·SVG를 모델에서 실행하지 않는다.
- 문서 표: `presentation={type:"table",source:"documents",title,columns:[문자열],rows:[{cells:[문자열],citations:[{chunkId,quote}]}]}`. 각 행의 1~5개 인용은 제공된 근거 ID와 정확한 원문에 연결한다. 모델의 문장·표 생성은 한 번 호출하며 행/인용이 무효이면 전체 모델 결과를 거절하고 발췌로 전환한다.
- 표 요청의 모델 내부 JSON은 `{answer:{insufficient,statements,table}}`다. 루트는 객체이고 `answer`의 중첩 `anyOf`로 정상 답변(`insufficient=false`, 문장 1개 이상·실제 표)과 근거 부족(`insufficient=true`, 빈 문장·`table=null`)을 분리한다. 기본 문장 모델 JSON은 기존 구조를 유지한다. 서버는 같은 일관성과 정확한 인용을 다시 검증한다.
- 운항 표는 같은 표 구조에서 `source:"operations"`, 행 `citations:[]`이며 실제 조회 자료로 구성한다. 질문·작업 종류에 맞는 운항 맥락이 있을 때 사용하고, 선박이 선택됐다는 이유만으로 규정 비교 표를 운항 표로 바꾸지 않는다.
- 운항 차트: `presentation={type:"chart",source:"operations",chartType:"line"|"bar",title,xLabel,yLabel,unit,points:[{label,value}]}`. 숫자는 조회·계산한 유한한 0 이상 값만 사용한다. 없는 값·공식 CII 등급을 모델이 만들어 채우지 않는다.
- 표는 최대 8열·50행, 셀 1,000자·열 제목 80자·제목 200자다. 차트는 최대 100점, 점 이름 80자·단위 40자다. 한도를 넘는 자료는 `truncated`, `totalRows` 또는 `totalPoints`로 표시 개수와 전체 개수를 구분한다.
- `answer.operations`의 합계·건수는 선택한 전체 기간 자료로 계산하며, 기존 요약 그래프·기록 표용 `rows`는 처음 200건의 미리보기다. `rowsTruncated`, `totalRows`로 전체와 표시 범위를 안내한다. 전역 운항 조회 API와 원본 기록은 바꾸지 않는다.
- 자료가 없거나 지원하지 않는 시각화라면 `presentationNotice`로 사유를 표시하고 가능한 기존 문장·인용을 유지한다. 원문 PDF의 표·그림은 기존 원문 열람 링크로 볼 수 있다.
- 화면은 모델 문자열을 HTML로 해석하지 않고, 표의 행/열·차트 축·단위·자료 표·원문 인용을 접근 가능한 요소로 표시한다. 무효 표현 데이터는 화면 오류 대신 안내와 기존 답변을 표시한다.

## 3. 입력량과 호출 예산

- 모델 사용자 메시지의 질문·근거 JSON을 최대 8,192 UTF-8 바이트로 제한한다. 근거를 순위대로 완전한 단위로 선택하며 원문 중간을 자르지 않는다. 생략·전달 불가를 알리고 근거가 없으면 호출하지 않는다. 이 값은 실제 토큰 수나 모델 문맥 크기 보장이 아니다.
- `generationStats={candidateEvidence,usedEvidence,omittedEvidence,payloadBytes,payloadByteBudget,modelCallAttempted}`로 허용되는 입력의 선택 개수·크기와 실제 모델 HTTP 호출 여부를 구분한다. 발췌·차트·호출 생략에서는 선택 통계가 있어도 `modelCallAttempted=false`다.
- 요청 시작 후 검색·선행 작업의 경과 시간을 제외한 28초 예산과 기존 25초 중 작은 값으로 모델 HTTP 제한을 정한다. 1초 미만이면 호출하지 않고 안내·발췌로 전환한다. HTTP 제한은 I/O 단계의 제한이며 전체 프로세스의 강제 종료 시한을 보장하지 않는다. 프런트의 32초 제한과 실제 전체 흐름을 별도로 확인한다.
- `timings={retrievalMs,generationMs,totalMs}`는 단조 시계로 측정한 0 이상 밀리초다. `totalMs`는 답변 계산 단계이며 이후 이력/감사 기록 저장과 선행 인증·HTTP 전달은 제외한다. 전체 API·브라우저 시간은 클라이언트에서 별도로 잰다. 비밀 키·URL·공급자 오류 원문을 포함하지 않는다.
- 런타임 문장 `text`·`quote`는 최대 4,000자, 모델 응답 content는 최대 128KiB로 검증한다. 실제 토큰 수 제한을 공급자에 임의로 추가하지 않는다. 과거 schema 1 평가의 사람 검토는 저장 당시의 구조·정확한 인용 계약으로 검증하여 새 런타임 길이 한도를 소급 적용하지 않는다.

## 4. 입력량별 평가

- `scripts/evaluate_llm_load.py`는 기존 고정 근거 평가 질문·기대 사실에 실제 seed 문서의 다른 절을 추가해 근거 수/길이를 바꾼다. 원문을 복제하거나 의미 없이 늘린 결과를 실제 문서 검색 규모 시험으로 주장하지 않는다.
- 기본은 오프라인 발췌 모드이며 `--mode llm`을 명시할 때만 설정한 실제 모델을 호출한다. 반복 `--case`·`--scenario`로 실행량을 제한한다. 기존 파일을 덮어쓰지 않고 모델 호출 전에 새 출력 경로를 확보한다.
- 질문·기대 사실·원문·입력 해시, 공급/선택 근거 개수·바이트, 모델/발췌 구분, 실행 시간·인용/출력 오류·원래 예외 클래스 이름을 기록한다. 의미 정확도는 `pending`으로 보존한다. 실제 API의 검색/인증/DB/브라우저 측정과 구분한다.

## 5. 수용 조건

- 표/차트 자연어 요청 → API의 자료·인용 검증 → 의미 있는 화면 표시 → 원문 열람을 확인한다.
- 빈 자료·미지원 그림·무효 인용/표·비정상 수치·큰 입력·남은 시간 부족·발췌 전환을 회귀 검증한다.
- 모의·실제 모델·DB/API·브라우저 검증 결과를 각각 기록한다. 일반 의미 품질과 전체 문서량별 검색 수용 기준은 별도 실측을 따른다.
