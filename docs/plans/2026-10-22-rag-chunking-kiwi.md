# 목차 청킹과 Kiwi BM25 개선

- 관련: [API 계약](../specs/api.md), [아키텍처](../architecture.md)

## 1. 배경과 목표

목차 항목과 쪽번호 분리, 목차의 heading 오인, 연속된 제목의 단독 청크를 줄인다. 검색의 한글 bigram을 설치된 Kiwi 형태소 분석으로 교체하고 해사 용어·불용어를 적용한다.

## 2. 범위

- 포함: 페이지 내 목차 항목 묶음, 연속 제목과 설명 결합, 공통 검색 토큰화, 사전, 회귀 검증.
- 제외: 원본 PDF/UI/DB 스키마·개정 관리 변경, 기존 DB 재청킹, 표 레이아웃 복원, 벡터·RRF.

- README, API 계약, 아키텍처, 변경 이력, 계획 색인.

## 5. 위험과 대응

- 목차 오인: 명시 목차 표제 또는 반복된 점선+쪽번호 근거 사용. 일반 본문 회귀 테스트.
- 검색 과확장: 문자열 부분 포함 대신 토큰/구 단위 일치, 확장은 한 번만 수행.
- 의미 손실: 부정어·수치·단위 보존, 제한된 불용어 목록.
- 느린 형태소 분석: 프로세스별 분석기 재사용, 영숫자 전용 구간은 정규식 처리. 문서 토큰/권한 인덱스는 캐시하지 않는다.
- 기존 문서는 자동 재청킹하지 않으며 같은 입력의 unchanged 동작을 유지한다.

## 6. 열린 질문

실제 질문 전체의 Recall@5 평가와 기존 문서의 명시적 재색인 경로는 후속 작업이다.
