## 1. 배경과 목표

사용자는 기존 실제 선박 데이터와 연결되는 공개 자료를 이용해 입항 조건 질문을 확장하고자 한다. 항구 파일을 수집했다는 사실만으로 실제 선박과 연결되거나 현재 입항이 허용되는 것은 아니다. 기존 IMO 식별자·MarineVessels·WPI를 실제 대조하고, 단위가 명시된 Wikidata 수량 명제를 추가 확보해 참조용 조건 비교의 가능 범위를 검증한다.

## 2. 초기 범위 (1단계)

- 포함: IMO 정확 일치, 공개 제원 후보의 단위·명제·파일 해시 추적, WPI 식별자·결측·중복 처리, 출처 값 비교 CLI, 실제 연결률과 부족 항목 기록.
- 제외: 현재 흘수 자동 추정, 현재 위치/AIS 연결, 입항 허가·항로 안전 판정, 데이터의 법정 검증값 승격, 운영 DB 변경, 화면·LLM 라우팅·PR 제출.
- 기존 MarineVessels의 단위·길이 기준·측정 시점은 문서에서 충분히 확인되지 않는다. 원본을 보존하되 자동 계산 입력으로 승격하지 않는다. 과거 흘수는 현재 흘수로 사용하지 않는다.

## 8. 실제 실행과 검증

기존 MRV IMO에 연결된 세 조합을 CLI와 순수 함수로 실행했다. 아래는 기존 공개 snapshot 간 수치 비교이며 현행 항만 조건을 증명하지 않는다. 원본 해시·명제·단위·부족 사유가 결과에 포함된다.

- Windows / Python 3.13.7, 기존 backend 잠금 의존성 환경 사용, 추가 패키지 없음.

## 9. 실행해 본 뒤 선택한 다음 대안

전 세계 모든 항구를 현행 입항 가능/불가로 분류하기보다 **대상 선박·항만·선석을 좁혀 공식 자료로 보강**하는 것이 현실적이다.

1. 이미 MRV와 IMO가 연결되는 시범 선박을 선택하고 선주·선급의 현행 LOA·폭·수면 위 높이를 확인한다. 현재 흘수는 적재 상태/선내 운항 입력에서 확보해야 하며 DWT·과거 흘수로 역산하지 않는다.
2. 선택 항만의 터미널·선석·접근 항로를 식별하고, 항만 당국 자료의 적용 시점·허용 제원·UKC 기준과 출처를 연결한다. WPI의 가장 깊은 부두 수심을 모든 선석에 적용하지 않는다. [공식 필드 설명](https://msi.nga.mil/api/publications/download?key=16920959/SFH00000/WPI_Explanation_of_Data_Fields.pdf&type=view).
3. 그 자료가 확보된 뒤 앱 인증을 유지하는 조회 경로와 LLM이 읽을 구조화 결과를 연결한다. 위치·현재 흘수가 기존 시스템에 있으면 재입력시키지 않고, 누락됐을 때만 보완 질문한다.

이번에 확인된 사실은 **기존 MRV와 공개 제원을 IMO로 연결하고 항구 참조값과 비교하는 기반은 만들 수 있다**는 것이다. 현재 확보 자료만으로 현행 입항 허가를 확정할 수 있다는 의미는 아니다.

AIS 원본은 [Fintraffic](https://www.digitraffic.fi/en/marine-traffic/), 단위·특수값은 [공식 OpenAPI](https://meri.digitraffic.fi/swagger/openapi.json), 치수 의미는 [USCG](https://www.navcen.uscg.gov/ais-class-a-reports)를 확인했다. CC BY 4.0 출처와 가공 내역을 snapshot·API에 보존했다. 선석 제원은 [Gothenburg Port Authority](https://www.portofgothenburg.com/maritime/berth-specifications/?epslanguage=en)의 HTML을 해시 고정해 추출했다. 기존 WPI의 유일 SEGOT 항목 `WPI:24020`과 명시적으로 연결했다.

추가로 운영사 [Seaway7의 Hawk 소개](https://www.seaway7.com/vessels/hawk/)를 확보했다. 이 페이지의 LOA 표기와 기존 Wikidata 길이는 다르며, 기존 일반 길이·운영사 LOA·deck breadth가 같은 지표라고 가정하지 않았다. 운영사 소개 페이지를 현재 법정 제원이나 AIS 신고값의 자동 대체값으로 사용하지 않는다. 불명확한 2015년 제원을 최신값으로 승격하는 대신, 단위·수신 시각이 있는 AIS 참조와 공식 선석 조건으로 시범 경로를 확장했다.

### 실제 API 확인

기존 해사 Bearer 경계 안에 `GET /api/maritime-data/port-reference-catalog`, `POST /api/maritime-data/port-reference-screen`을 추가했다. 앱의 문서 검색·LLM 프롬프트·화면은 변경하지 않았다. 서버 전용 파일 설정이 필요하고 인터넷 자동 수집은 없다. 매 요청 snapshot 검증·시각 재평가를 수행한다.

실제 MRV에 있는 **IMO 9240249**를 추가 AIS의 **RIX VENTA**와 연결했다. 수집본의 신고 길이 90m·폭 16m·흘수 4.9m로 다음 HTTP 결과를 확인했다.
