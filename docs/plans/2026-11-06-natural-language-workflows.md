# 자연어 조건·되묻기·다단계 조회와 후속 질문 통합

- 상태: 완료 (로컬·미제출)
- 작성: 2026-11-06
- 관련: [통합 답변 계약](../specs/integrated-answer.md), [업무 스킬](../specs/workflow-skills.md)

## 목표

기존 도구와 문서/항구 경로를 재사용해 자연어 선박·기간·연도 조건, 부족 입력 되묻기, 최대 4회 읽기 전용 도구 실행, 소유자 검증 후속 질문을 기존 질문 화면에 연결한다. 로컬 Qwen의 제안은 서버의 폐쇄형 계약으로 검증한다. 실제 선박 데이터·승인·공식 CII·SQL·쓰기 명령은 모델이 만들지 않는다. 개인 DB·기존 미커밋 변경·원격 PR을 보존한다.

## 단계

- [x] 현재 질문/스킬/계산·LLM 경로와 설치된 로컬 Qwen 확인.
- [x] 계약 확정·서버 조건 추출/검증·선택적 모델 action 선택·부족 입력 상태 구현.
- [x] 기존 운항 요약/MRV 참고 도구·선택 문서 실행, 비교·소유자 후속 질문 연결.
- [x] 기존 질문 화면의 실행 범위·되묻기·결과·출처 표시 연결.
- [x] 단위/보안·전체 회귀·실제 PostgreSQL/API·Docker 화면·실제 Qwen 검증과 기록·임시 환경 정리.

## 범위

선박 최대 2척, 연도 최대 3개, 일별 기간 최대 2개(각 시작~종료 366일 차이 이하), 전체 도구 호출 최대 4회다. 날짜/선박은 명시 문장·검증한 UI 선택·같은 소유자의 지정된 이전 실행 범위로만 결정한다. 모델 오류는 규칙/되묻기로 처리하고 임의 범위를 채우지 않는다. 항구 기능과 문서 전용/절차 질문의 기존 경계를 유지한다. 데이터가 없는 연도나 계산 불가 사유를 행에서 제외하지 않는다.

## 구현 결과

`question_intent.py`가 명시 연/월/일·ISO 날짜·최근 일수·상대 주/월·등록 선박 범위를 해석하고 `question_workflows.py`가 기존 운항/MRV/선택 문서 함수를 실행한다. 부족한 조건은 소유자가 확인한 부모 답변에 연결해 보완하며, 선박 버전/매핑/문서 권한을 재확인한다. 다른 질문·잘못된 부모·동명 선박·지원하지 않는 비교 기준·기간 과다를 임의의 실행 범위로 바꾸지 않는다. 선택 문서 양식은 원래 질문을 유지한다. 비교는 동일 종류 결과의 산술 차이이며 실제/가상 혼합·기록 없음·0 기준 변화율은 별도 처리한다.

기존 통합 질문 화면에 실행 범위·조건 보완·여러 도구 결과·산술 비교를 연결했다. 별도 업무 페이지·새 SQL 테이블·의존성을 추가하지 않았다. 코드/명세/구조/데이터 모델/사용법과 선택적 `HAEDAP_PLANNER_MODEL` 설정을 정리했다.

## 검증과 증거

- Docker PostgreSQL의 전체 backend **1,011 passed / 4 skipped** 이후 날짜/선박 경계를 추가 보완하고 최종 관련 **402 passed / 0 skipped**, 새 모듈 단위 **24 passed**를 확인했다. 검사 범위는 겹친다. 4건 건너뜀은 전체 검사 시 별도 적재 DB 환경변수 미설정에 따른 것이고 적재 관련 검사에서는 실행했다.
- frontend 단위 **26개**, production 빌드, Docker 전체 화면 **26개** 통과. 최종 표시 보완 후 새 경로 **3개**와 실제 API/DB 화면 **1개**를 재실행했다. 실제 선박 2개 연도·자료 없는 후속 연도·참고 동의·문서 선택·가상 운항 비교·모바일 범위를 확인하고 screenshot을 검토했다.
- 격리 DB에 실제 MRV **80,552행**, Synthetic Noon **4,380행**, DWT 참조 **25,240행**을 적재했다. YEOMAN BANK/SUNNANVIK의 2021/2022 참고 계산을 기존 Tool과 대조했다. 가상 SIM-BULK-01의 기존 365일 자료만 별도 sample 앱 선박으로 복사해 월 합계를 검증했다. 실제 MRV 앱 선박에는 가상 일별 기록을 채우지 않았다. 실제 API **14개**를 단언하고 최종 코드로 모두 재실행했다.
- 실제 Ollama **Qwen2.5 0.5B**와 API를 연결한 **4개** 질문에서 최종 작업/결과를 확인했다. 모델 선택 **2개**, 모델 unknown 등에 따른 규칙 대체 **2개**다. 약 0.87–3.56초의 해당 요청 시간은 이 소수 사례의 관측값이며 일반 모델 정확도·성능 평가가 아니다. 최초 3B 시도는 18초 제한 초과, 초기 날짜 포함 모델 출력은 검증 실패하여 폐기했다. 따라서 모델은 승인된 action만 제안하고 날짜·식별자·SQL·수치는 서버/기존 도구가 결정한다. 인용 답변 생성·범용 자율 에이전트 성능 검증은 포함하지 않는다.
- backend **11개 runtime SHA256**이 로컬과 일치하고 MRV 전체 행 MD5 **`47f6876da973fe710a15e0d2491caa1e`**가 모든 검사 후 동일했다. 기존 1.4 항구 catalog SHA256 **`059a09cddd15b51c5dc699d9f318db1b5ab1f2d61e52cecd89fefa9d9d11b128`**도 유지했다.
- 로컬 증거: `output/natural-language-20261106/`의 `backend-full.txt`, `backend-loaded-final.txt`, `unit-final.txt`, `docker-e2e-final.txt`, `final-ui.txt`, `actual-summary.json`, `actual-responses.json`, `actual-qwen-api.json`, `final-verification.json`, screenshot과 재현 스크립트. `output/`은 git 제외된 로컬 검증 자료다. 전용 Docker 프로젝트를 `down`으로 정리하고 모델을 unload했다. 개인 DB·기존 `.env`·원본 데이터·기존 작업·원격 PR은 보존했다.

## 남은 한계

제한된 읽기 전용 작업 확장이다. 임의 표현/다국어 전체·복잡한 원인 분석·여러 단계의 자율 쓰기·항차/연료/기관별 필터·공식 CII/입항 허가는 지원하지 않는다. 애매한 비교 기준은 날짜/대상을 다시 묻는다. Qwen 0.5B 선택 품질을 보장하지 않으며 팀의 실제 모델·자료·질문으로 별도 평가해야 한다. 새 기능의 원격 PR·배포는 수행하지 않았다.
