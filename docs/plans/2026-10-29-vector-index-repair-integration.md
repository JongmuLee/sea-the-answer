# 벡터 색인 복구와 팀 브랜치 호환성 검증

- 상태: 완료
- 작성: Codex · 2026-10-29
- 담당: 문서/RAG
- 관련: [자동 색인 계약](../specs/rag-index-jobs.md), [평가 질문](../rag-evaluation-questions.json)

## 1. 배경과 목표

재사용 ndarray와 신규 list 벡터가 한 배치에 섞이면 Chroma 검증이 실패한다.
입력 형식을 통일하고 최신 upstream/main 및 cxo/feature/ci-verification과의
텍스트 충돌뿐 아니라 저장 경로·마이그레이션·CI 테스트 호환성도 확인한다.

## 2. 범위

- 포함: 벡터 저장 오류 수정, 재현 테스트, 팀 변경과의 통합 검증.
- 제외: 실제 앱 재시작·데이터 수정·대량 재색인, 커밋·푸시.
- 기존 평가 문서 변경은 보존한다. 사용자 승인에 따라 두 원격 브랜치를 실제 통합한다.

## 3. 단계

- [x] 벡터 혼합 배치 실패 재현 및 수정, 재실행 검증.
- [x] 최신 두 원격 브랜치 충돌·저장/인증/테스트 변경 확인 및 호환성 반영.
- [x] backend 전체 테스트와 격리 Docker E2E, 결과 기록.

## 4. 영향 받는 파일·문서

rag_vector.py, 벡터 회귀 테스트, 통합 결과에 필요한 최소 연결부 및 관련 문서.

## 5. 위험과 대응

실제 DB는 검증에 쓰지 않는다. 격리 PostgreSQL·임시 Chroma를 사용한다.
머지의 자동 성공도 기능 호환성을 보장하지 않으므로 메타데이터 저장 후 작업 생성과
인증/색인 마이그레이션의 동시 적용을 따로 검사한다.

## 6. 열린 질문

사용자가 배포하기 전 실행 중인 앱에는 수정이 적용되지 않는다.
