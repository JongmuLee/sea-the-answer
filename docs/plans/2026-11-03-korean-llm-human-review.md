## 1. 배경과 목표

기존 16문항 평가 결과는 의미 정답성을 `pending`으로 남긴다. 인용 일치와 한글 포함만으로 의미 정답을 주장하지 않는 경계는 유지하면서, 사람이 기대 사실·실제 답변·원문 문맥을 대조한 결정을 저장하고 집계할 수 있게 한다.

## 2. 범위

- 포함: 저장된 평가 JSON의 검토표 생성·검토 요약 CLI, 원본 해시 연결, 자료 변경 감지, 오류·미검토·발췌 결과 분리, 회귀 테스트·재현 안내.
- 제외: 모델 호출·다운로드, 검색·프롬프트·인증·화면 변경, DB 변경, 의미 정답 자동 판정. 사용자 지시에 따라 PR #14 및 해당 브랜치는 별도 지시 전까지 변경하지 않는다.

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 유효 인용을 의미 정답으로 오인 | 모든 검토는 pending에서 시작, 사람의 명시적 결정만 집계 |
| 다른 평가 결과에 검토표 재사용 | 원본 결과 SHA-256과 사례 ID·고정 입력 일치 검증 |
| 발췌·실행 오류를 실제 모델 합격으로 표시 | 모드와 기술 오류를 별도 집계하고 전체 합격 제한 |
