## 1. 배경과 목표

10월 29일 교수 피드백은 요청한 표·그림의 화면 표시와 데이터양에 따른 정확도·시간 문제다. 기존 고정 운항 UI를 넘어 요청에 맞춘 표·차트를 연결하고, 입력량·검색·생성·전체 시간을 구분해 검증한다.

## 2. 범위

- 포함: 문서 근거 표, 실제 운항 표·선/막대 차트, 요청 해석·서버 검증·화면 표시, 미지원/빈 자료 안내, 입력 바이트·남은 생성 시간 예산, 입력량별 재현 CLI·회귀·통합 검증.
- 제외: 새 이미지 생성·원문 그림 자동 추출·RAG 알고리즘·DB 스키마 변경·유료 모델·새 모델 다운로드. PR #14 및 해당 브랜치는 별도 지시 전까지 변경하지 않는다.
- 제출: 개인 저장소의 기존 작업 브랜치에 먼저 반영하고 같은 팀 PR #22를 갱신한다.

## 4. 영향 받는 파일·문서

| 경로 | 변경 |
|---|---|
| `backend/api/llm.py`, `store/answers.py`, 표현 모듈·테스트 | 근거 표·자료 기반 차트·입력량·시간 예산 |

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 인용만 맞는 잘못된 표·숫자 | 행별 인용·실제 운항 수치만 사용·의미 검토 별도 |
| 큰 입력·많은 행 | 완전한 근거 단위의 바이트 예산·표시 한도·누락 안내 |
| 시간 제한 혼동 | 단계별 시간·예산·실제 브라우저 확인 |

## 6. 열린 질문

- 원문 그림 추출·새 그림 생성은 별도 팀 범위다.
- 전체 문서량별 검색 규모 시험은 RAG 담당자의 실제 모듈과 후속 검증한다.

## 7. 진행 기록

- 2026-11-03: 사용자 지시로 PR #22의 범위를 교수 피드백 대응까지 확장했다. 개인 저장소 우선·PR #14 제외 원칙을 유지한다.
- 2026-11-03: 표·차트·입력/시간 예산·표시 한도·CLI와 회귀 구현. 실제 데이터 흐름의 초기 Docker 검증은 통과했으며 미리보기 추가 후 백업 복구/로그인 검사 1건의 관측을 보완해 재검증한다. 로컬 3B 모델의 지연·표 생성 미확인과 입력량 비교 한계는 변경 이력에 기록했다.
- 2026-11-03: [최종 격리 검증](https://github.com/cxo-ca/sea-the-answer/actions/runs/41615879164)은 backend 624 통과·4 건너뜀, frontend 26 통과·빌드, Docker e2e 12 통과·정리 성공이다. 새 표현 흐름과 전체/미리보기 구분을 확인했고 복구 HTTP 200·세션 초기화도 확인했다. 실제 모델 의미 품질 수용과 전체 문서량별 검색 시험은 열린 질문으로 유지한다. 개인 작업 브랜치와 동일 PR #22에 구현·검증·한계를 반영했다.
