- 상태: 완료 (로컬 구현·검증, 팀 검토 전)

- 관련: [평가 사용법](../retrieval-evaluation.md), [ADR 0017](../adr/0017-bounded-chunk-token-reuse.md)

## 1. 배경과 목표

955청크 초기 평가에서 검색 p50 약 7초. 별도 프로파일에서 전체 4.525초 중 청크 토큰화가 4.475초를 차지했다. 현재 권한 경계와 검색 순서·점수를 유지하며 반복 분석을 줄인다.

## 2. 범위

- 포함: 내용 기반·크기 제한 토큰 캐시, 회귀·권한 변경·새 내용·동시 접근 검증, 동일 질문 20개 재평가와 기존 결과 대조.
- 제외: 결과/사용자 질의/권한/인덱스 캐시, 검색 기준 변경, DB 스키마·화면·LLM 라우팅 변경.

## 4. 영향 파일

`backend/api/rag_retrieval.py`, 관련 테스트, 검색 평가 결과, API 검색 계약·구조·ADR·색인·변경 이력.

## 5. 위험과 대응

- 권한·활성 개정·선택 문서는 매 요청 DB에서 확인하고 캐시는 현재 후보의 분석에만 사용한다.
- 제목·출처·절 제목·본문 전체로 키를 만들고, 결과는 현재 행으로 생성한다.
- 원문 문자열·질의·인덱스를 보관하지 않으며 프로세스 내 토큰도 크기·개수 제한과 LRU로 제거한다. 토큰에도 민감한 단어가 포함될 수 있음을 문서화한다.
- 초기 검색·캐시 초과 corpus는 느릴 수 있으므로 warm 결과를 전체 성능으로 일반화하지 않는다.

## 6. 열린 질문

실제 선내 문서 규모·장비·동시 사용자 기준으로 캐시 크기와 응답 시간 목표를 합의해야 한다.
