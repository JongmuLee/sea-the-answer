# 해사 질문 평가셋과 검색 성능 측정

- 상태: 완료
- 작성: 손태호 · 2026-10-28
- 담당: 역할4
- 관련: [BM25 계획](2026-10-14-bm25-retrieval.md), [검색 평가 사용법](../retrieval-evaluation.md)

## 1. 배경과 목표

기존 검색 단위 테스트와 별도로 저장소의 실제 문서 본문에 질문–정답 근거를 연결하고, 운영 검색 함수의 검색 성공률·Recall@5·MRR·처리 시간을 재현 가능하게 측정한다.

## 2. 범위

- 포함: 기본 문서 스냅샷, 실제 전처리·검색 함수, 수동 작성 질문과 인용 라벨, 답이 없는 질문의 후보 노출 진단, JSON/CSV/Markdown 결과.
- 제외: 운영 DB 읽기·변경, 인증·권한 평가, LLM 호출·의미적 정답성, 실제 긴급 운항 판단, 화면·API 변경. 요약과 가상 자료를 공식 원문으로 취급하지 않는다.

## 3. 단계

- [x] 질문·근거 라벨 작성 및 원문 존재 검사
- [x] 동일 검색 함수를 호출하는 CLI와 지표·결과 기록 구현
- [x] 지표 계산·라벨 오류·재현성 테스트와 실제 평가 실행
- [x] 결과·한계·실행법 및 문서 색인 갱신

완료 조건: 검색 실패도 숨기지 않고 기록하며, 근거가 없는 질문의 검색 결과를 환각 발생으로 단정하지 않는다. 운영 검색을 평가셋에 맞춰 변경하지 않는다.

## 4. 영향 받는 파일·문서

`scripts/evaluate_retrieval.py`, `backend/knowledge/evaluation/maritime-questions.json`, `backend/tests/test_retrieval_evaluation.py`, 사용법·색인·변경 이력. 런타임·DB 스키마 변경 없음.

## 5. 위험과 대응

- 소규모 작성자 평가셋 편향: 자료·질문 유형별 결과와 실패를 공개하고 팀원 검토·미공개 평가셋을 후속 과제로 남긴다.
- 환경별 처리 시간 차이: 환경·반복 횟수·초기화와 반복 시간을 분리 기록한다. API/LLM 지연과 구분한다.
- 원문 변경: 원문 해시와 검색·전처리 코드 해시를 기록하고, 인용이 사라지면 실행을 중단한다.

## 6. 열린 질문

선내 장비·실제 사내 매뉴얼·전문가 정답 검수 및 배포 승인 성능 목표는 팀과 별도 합의가 필요하다.
