## 목표와 범위

실제 입항 검토에 부족한 조건을 개별 확인 항목으로 제공하고 핀란드 밖 공식 AIS·항만 자료를 확보한다. 현재 제원·기상·항로·예선·승인 자료가 없는데도 입항 가능으로 확정하지 않는다. 기존 MRV/DWT·계정·RAG/LLM·이전 미커밋 질문 보완은 보존한다. 원격 push/PR 갱신은 이번 요청에 포함하지 않는다.

## 원칙

- 자료 없는 실시간 기상·현재 실측값·예선 확보·항만 승인·안전 여유 기준은 생성하지 않는다.
- 전 세계·전체 일자 데이터로 확대 해석하지 않는다. 기간·지역·부분 수집·실패·회원/키 필요를 구분한다.
- AIS 출처를 추가해도 최신값 하나를 임의로 선택하거나 국가별 충돌을 삭제하지 않는다.
- 공공 선석 수심·부두 길이는 허용 선박 흘수·길이로 바꾸지 않는다. 조건부 원문은 보존한다.
- 네트워크 수집은 명시 오프라인 준비만 수행하고, 파일/응답 크기와 실행 시간을 제한한다.
- 실제 입항 허가와 선장/항만의 운항 결정은 이 참조 비교가 발급하지 않는다.

## 접근 기록

- 노르웨이 해안청의 공개 AIS TCP `153.44.253.27:5631`은 8초 연결 시간 초과였다. 공식 Kystdatahuset HTTPS GeoJSON은 인증 없이 HTTP 200으로 접근됐다. 인증이 필요한 API는 우회하지 않는다.
- 덴마크 AIS 이전 다운로드 호스트는 인증서의 호스트 불일치로 실패했다. 인증서 검증은 해제하지 않는다.

- `tools/navigation_readiness.py`가 현재 검증 제원, 현재 실측 흘수, 전체 접근 경로, 수위/기상/선저 여유, 실제 도선/예선, 선종/화물/터미널, 최신 공고/선석 배정/승인의 **7개 미확인 영역**을 제공한다.

## 검증 결과

- 격리 Docker PostgreSQL 18·FastAPI production·Next.js production, 일반 viewer 로그인·CSRF로 검증했다. 실제 MRV **80,552행**·합성 Noon **4,380행** 등 기존 CSV를 임시 DB에 적재했다. 개인 DB는 사용하지 않았다.
- 전체 backend **932 passed / 4 skipped**(적재 DB 별도 변수 미설정). 이후 해당 변수도 설정한 최종 관련 backend는 **178 passed / 0 skipped**다. 두 범위는 겹치므로 합산하지 않는다. frontend 단위 **26개**, production 빌드, 기본 Docker E2E **21개**가 통과했다.
- 실제 HTTP **36개**(기존 질문 26개와 새 catalog/항구·시나리오·노르웨이 선박·잘못된 입력 10개)를 검사했다. 정상/보류/잘못된 입력의 상태와 실제 선석·숫자를 대조했으며, 단순 HTTP 200을 성공으로 보지 않았다.

- 실제 viewer의 화면 E2E **1개**로 새 항구 질문, 출처별 건수, 가정 입력·결과 변화, 노르웨이 미확인 사유와 데스크톱/모바일 표시를 검증했다. 첫 캡처에서 공통 알림 스타일이 조건 항목을 가로로 배치하는 문제를 확인해 해당 새 컴포넌트에서만 세로 배치로 보완했다. 마지막 화면 검증·캡처는 이 보완을 포함한다.

## 남은 실제 운항 데이터와 경계

현재 선내 검증 제원·실측 흘수/적재 상태, 접근 경로 전체의 최신 수로 자료, 예정 시점의 현장 기상/수위, 계산·승인된 동적 UKC, 도선/예선 배정, 터미널/화물 수락·최신 항만 승인 정보는 확보되지 않았다. 공개 위치 보고나 사용자의 가정값으로 이 증빙을 채우지 않았다. 실제 입항 가능/불가 자동 확정 기능이 완료된 것으로 보고하지 않는다.

덴마크 AIS 구 다운로드 호스트의 TLS 오류·노르웨이 TCP 연결 제한은 접근 기록에 남겼다. 노르웨이는 공개 HTTPS로 필요한 원문을 확보했으며, 덴마크 AIS 전체 일자 파일은 이번에 확보했다고 주장하지 않는다. 운영 배포/원격 PR 갱신은 별도 요청 전까지 수행하지 않는다.
