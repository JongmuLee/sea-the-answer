## 1. 배경과 목표

22개 실제 API 질문에서 부정·수치 필터·정렬이 기본 결과와 동일하게 반환되고, 유사 동사와 짧은 후속 질문이 문서 검색으로 빠지는 현상을 확인했다. 지원하는 조건은 결과에 적용하고, 지원하지 않는 조건은 안내한다. 기존 문서 전용 요청·규정/절차 검색·인증·선박 매핑과 실제 입항 미판정을 유지한다.

## 2. 범위

- 포함: 제한된 한/영 유사 표현, 명시적 공개 선석 제한값 필터·정렬, 공개 수치 초과/자료 부족 필터, 소유한 이전 답변을 지정하는 항구·선석 후속 질문, 적용 조건·전체/표시 건수·미확인값 안내.
- 제외: 범용 LLM 라우팅, 실제 입항 가능/불가 판정, 새 DB 스키마, 새로운 항구·위치/항로 추천, 원격 PR 갱신.

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 불가능 요청을 실제 입항 불가로 변환 | 공개 수치 초과와 분리하고 확인 안내 |
| 사용자 입력 치수를 현재 선박값으로 사용 | 선석의 명시적 공개 제한값만 필터; 가정 선박 치수는 계속 거절 |
| 다른 사용자/선박/탭의 문맥 섞임 | 명시 이전 답변 ID, 소유자 JOIN, 선택 선박/버전·현재 매핑 재확인 |
| 필터로 누락값이 보이지 않음 | 비교 전체·표시·숫자 미확인 제외 건수 보존 |
| 오래된 이력 숫자 재사용 | 이력은 대상/조건만 연결하고 새 카탈로그·현재 DB로 재조회 |
| 일반 문서 질문 가로채기 | 문서 전용·규정/절차 우선, 후속 질문을 제한된 형태로 인식 |

## 6. 구현 결과와 검증

`backend/api/navigation_intent.py`에서 명시 공개 제한값의 최대 3개 AND 수치 조건과 항구별 정렬을 분리했다. 기존 도구가 계산한 값·출처·부분 판정은 보존하고 결과의 복사본만 선택한다. 필터에서 한계값을 모르는 선석은 제외 수를 표시하고, 정렬의 미확인값은 마지막에 둔다. 0건에도 대상 항구·출처는 유지한다.

`navigation_query.py`의 좁은 분기와 기존 `controller.jsx`/`NavigationAnswer`를 보완했다. 별도 스킬·라우터·DB 테이블·LLM 추론은 추가하지 않았다. 독립 질문은 이전 조건을 초기화하며, 제한된 후속 질문만 명시한 소유자 답변의 대상/조건을 연결한다. 같은 선박 버전·IMO·현재 매핑이 아니면 이전 자료를 반환하지 않는다. 새 항구는 이전 선석을 해제한다.

| 실제 질문 | 수정 전 | 수정 후 |
|---|---|---|
| 헬싱키 흘수 제한 8m 이상 | 기본 8개 모두 | LHB/LHC/LHD/ERA 4개 |
| 헬싱키 흘수 한계 큰 순 | 원문 순서 | LHD(10.8), ERA(9.3), LHC(8.9), LHB(8), EKL(7.9), EMA(7), EO1(6.7), EPL(5.3) |
| 입항 불가능한 선석만 | 기본 8개 모두 | 실제 불가 미판정 안내·공개 초과 조회 제안 |
| 공개 제한 초과 선석만 | 미지원 | EPL 1개·실제 입항 불가 판정 아님 |
| 이용할/받아줄 수 있는 항구 | 문서 검색으로 이탈 | 항구 비교 |
| 그럼 헬싱키는? | 문서 검색으로 이탈 | 지정한 소유자 답변의 문맥·현재 자료로 재조회 |
| 20m 이상 / 폭 제한 미확인 / ft | 조건 무시 가능 | 0건 / 미확인 8개 제외 / 미지원 안내 |

- 검증 환경: 격리 `haedap-portconditions-20261105` Docker PostgreSQL 18·FastAPI production·Next.js production, 실제 viewer 로그인/CSRF, 답변 생성 LLM 미설정. 개인 DB·기존 운영 설치 파일·원격 PR은 변경하지 않았다.
- 실제 MRV 80,552행·Noon 4,380행 등 기존 CSV 적재. 같은 날 확보한 읽기 전용 catalog SHA256 `a99f298e5679997845d7e6f28e2024af36ae3234639788be9ccae0848e1e8db2`(MRV 연결 AIS 304척, 2항구 53그룹)를 사용했다. 원래 수집본을 덮어쓰거나 시각을 바꾸지 않았다.
- 26개 실제 HTTP 질문의 대상·선석·조건·미지원 상태와 같은 뜻 6개 질문의 구조를 검증했다. 평가 시각만 제외하고 비교했으며, 후속 질문의 이전 ID 차이는 결과 목록 단위로 대조했다. 3개 runtime 소스가 로컬 SHA256과 일치한다. MRV 전체 내용 MD5는 전후 `47f6876da973fe710a15e0d2491caa1e`로 같다.
- 전체 pytest 876 통과/4 건너뜀(적재 DB 환경변수 미설정); 최종 관련 pytest는 적재 DB 변수도 지정해 113 통과/0 건너뜀. 범위는 중복된다. frontend 단위 26개·production 빌드·기본 Docker E2E 20개·최종 실제 데이터 화면 E2E 1개를 확인했다. 질문 소유자 SQL·다른 사용자·선박 변경·버전·현재 매핑 변경·현재 자료 재조회·문서 경로 보존이 검사에 포함된다.
- 중간 실패: 넓어진 질문 분기가 입항 방법 질문을 가로챈 회귀를 문서 우선 규칙으로 수정했다. 첫 전체 pytest는 동시 자료 적재의 테이블 잠금으로 1건 실패했고, 적재 종료 후 직렬 재실행에서 통과했다. 최종 관련 검사는 최신 조건 후속/영문 보완도 포함한다. 모바일 캡처는 메뉴 전환 종료를 기다려 다시 검사했다.
- 로컬 증거: `output/navigation-query-check-20261105`는 수정 전, `output/navigation-conditions-20261105`는 수정 후 전체 응답·전후 대조·runtime 해시·검사 로그·화면 이미지다. Git 제외 검증 자료이며 테스트 질문에는 일회성 격리 계정을 사용했다.
- 검증 종료 후 해당 Compose 프로젝트의 컨테이너·네트워크를 정리했다. 개인 DB와 다른 프로젝트 컨테이너는 종료/삭제하지 않았다.

남은 범위는 범용 자연어/LLM 도구 선택·임의 복합 조건·실시간 입항 허가·미확보 항구/항로/기상이다. 이번 기능은 정해진 조건을 해석하고 기존 데이터와 비교하는 경로이며 이런 범위를 구현했다고 보지 않는다.
